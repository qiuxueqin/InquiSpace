# 知境 · 阶段一交互原型

依据阶段一设计及“减少填写、由 AI 整理报告”的要求改版，并于 2026-11-04 简化师生界面。教师一句话生成方案，学生在对话中表达思考，报告优先呈现小结、图表和建议。内部校验与运行记录不进入师生页面。供原型评审和前端实现交接。

## 打开和运行

打开本目录的 `index.html`，样式、脚本与图标均已内置，不依赖 CDN 或模型账号。推荐用本地服务体验：

```sh
node serve.mjs
```

访问 `http://127.0.0.1:4173/`。服务仅监听本机，只有一个 HTML 入口。

本轮交互和验证见 [简洁界面改版说明.md](./简洁界面改版说明.md)。[AI协作改版说明.md](./AI协作改版说明.md) 和 [验证记录.md](./验证记录.md) 保留此前改版记录；以本说明及当前页面为准。

## 推荐体验顺序

1. 教师点击“创建探究任务”，写一句教学需求；学科、年级已有默认值，参考资料选填。也可选择示例快速体验。
2. 点击“生成教学方案”，查看“和谁对话、探究什么、课堂安排”。缺少历史时间时补充这一项即可；详细选项收在“更多设置”中。
3. 内部自动完成发布校验，只在缺少信息时提示需要补充什么。教师可按需展开“和角色试聊”；改写可撤销，修改后会重新校验，无需操作检查按钮。
4. 点击“发布给学生”，选择学生，勾选一次教学内容确认。发布后保存当前版本，已有历史记录保留。
5. 切换学生视角，进入获授权任务，直接提问、追问、表达判断或说明不确定之处。不必填写角色观点、结论或反思表格。
6. 每轮完成后，可选择“需要更多证据 / 暂时赞同 / 有不同解释”，再在聊天里说理由。选择和收藏均为可选，不影响结束探究。
7. “我的学习报告”随对话更新。点击“结束探究”即可保存报告并同步教师，无需另填成果；如有误解，可选填一句补充或更正。
8. 教师报告先展示课堂小结与教学建议，再展示进度环图、探究行为条形图和学生学习情况。点击图表回查原话与来源；学生详情默认展示学习报告，完整对话按需展开，没有运行轨迹或 JSON。
9. 通过“本次发布 / 历次发布 / 第 N 次发布”查看相应报告，旧版已提交成果仍可只读查看。点击“导出报告”下载当前任务、当前范围的 HTML 图文报告，可在浏览器打开或打印。
10. 任务归档后仍保留记录，教师可恢复。原型中的账号切换仅供演示。

顶部仅保留简短演示标识和“使用帮助”。轮次和截止时间通过教师配置并发布后生效。

## 实际能力与模拟边界

| 内容 | 本原型行为 |
| --- | --- |
| 页面、表单、弹窗、原文抽屉 | 实际可交互；包含手机单列布局、焦点循环和 Escape 关闭 |
| 多任务、版本、会话、摘录、学习报告、评阅 | 浏览器 localStorage 持久化；发布冻结及历史快照在本地模拟 |
| 身份和授权 | 界面按演示身份与任务名单过滤；不等同于真实认证或后端鉴权 |
| 一句话方案与预检 | 本地规则模板、字段校验和五类示例；没有模型推理、史实或语义核验 |
| 自动学习报告 | 从学生原话提取起点、判断、疑问，按关键词归类；角色观点单独展示，不补写缺失结论 |
| 教师图表与观察 | 从当前范围内的实际会话、学生表达、来源点击与判断选择聚合；不生成能力分或学习成绩 |
| 对话及追问 | 关键词与模板生成演示回答；只演示部分典型情境 |
| 来源与资料冲突 | 内置示例支持 PDF 页、TXT 行定位和并列引用；不是实际 PDF.js 或语义检索 |
| 新增 TXT | UTF-8 本地读取，空白或编码错误标为失败；不自动生成引用或参与语义回答 |
| 新增 PDF | 未接入解析，明确显示失败，解除关联后才能继续发布 |
| 上传限制 | 每版本最多 10 份，单文件 10 MiB；纯前端 TXT 读取额外限制 100 KiB |
| 分段输出、停止和重试 | 计时器与状态模拟；保存部分块，失败/停止不计完成轮数，重试不重复新增用户问题 |
| 截止和轮次 | 阻止新提问，仍可查看报告、结束探究；建议时长仅作提示 |
| 内部检查与记录 | 保留本地运行事件、边界检查、风险位置；师生页面不展示技术日志、JSON 或运行步骤。教学备注按需填写 |
| 导出 | 导出当前任务及所选发布范围的 HTML 图文报告，包含小结、图表、学生报告；不包含运行日志或其他任务数据 |

演示讲义是自编文本，不能作为真实史实、人物原话或产品验收依据。正式版仍需按既定 React / TypeScript / Ant Design / FastAPI 方案接入模型、PDF 解析、检索、数据库、认证、服务端版本事务和事件流。

## 数据保护与检查工作区

- 普通入口使用 `zhijing-opendesign-v2`。
- `http://127.0.0.1:4173/?review=qa#tasks` 使用 `zhijing-opendesign-v2-qa`。本轮全部浏览器测试数据在此隔离工作区中。
- 旧 `zhijing-opendesign-v1` 存储不删除；当前工作区的历史版本、对话和已提交成果仍可在报告中查看。
- 首次修订前完整副本保存在工作区 `work/prototype-before-LJKOdoZV/opendesign-prototype/`。
- AI 协作改版前另存完整副本：`work/prototype-ai-before-TwBg2GFH/opendesign-prototype/`。没有清空任何演示存储或用户历史任务。
- 简洁界面改版前另存完整副本：`work/prototype-simple-before-LilP42/opendesign-prototype/`。
- 本地存储只属于当前浏览器与来源地址；换浏览器、换端口或清除站点数据不会自动同步。正式数据需由后端持久化。

## 构建与测试

```sh
node --test tests/model.test.cjs
node --check src/model.js
node --check src/app.js
node build.mjs --replace-generated
```

47 项状态规则测试通过，覆盖原有版本与会话约束、新生成/预检流程、来源行为去重、学生与角色观点隔离、无成果表结束、报告更正及图表聚合。旧 `submit` 测试仅用于历史兼容，不代表新界面仍要求三个成果必填项。这些测试不能替代真实服务与模型验收。

## OpenDesign 与后续开发

可将独立的 `index.html` 作为 HTML 原型导入 OpenDesign，保留视觉母版后再拆分 React 组件。本轮没有验证 OpenDesign 客户端的导入、可视化修改和导出流程。

若已在 OpenDesign 修改过 `index.html`，先另存导出稿，再决定是否从本目录源文件重新构建。构建脚本默认拒绝覆盖已有 HTML，需要显式传入 `--replace-generated`。
