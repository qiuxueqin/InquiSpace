## 1. 通用协议

- Base path：`/api/v1`。除上传、原文件、事件流和 HTML 报告导出外使用 JSON UTF-8；文档 v1.1 不等于 API 路径升级。
- JSON camelCase，数据库 snake_case；UUID 字符串；时间戳 ISO 8601 UTC。
- 认证：HttpOnly `session` Cookie；所有写操作携带 `X-CSRF-Token` 并校验 Origin。登录只做 Origin 校验，成功后返回 CSRF token。
- teacher：仅任务 owner；student：当前 task_members 成员且仅访问自己的业务对象。
- 不可见对象 404；角色不能执行操作 403；无有效登录 401。
- 需要修改现有资源时，按下表使用 `If-Match: "rev-3"`；数字对应资源 revision 或 rowVersion，不是 versionNo。缺失为 428，过期为 412 `REVISION_CONFLICT`。
- 所有创建/确认/发布/提交/结束会话/归档/启动运行的 POST（除登录、退出、取消）要求 `Idempotency-Key`，1～128 字符，作用域为 userId + method + path + key。相同 key 和请求返回原资源；不同请求复用 key 返回 409。记录保存至少 24 小时。先检查当前权限，再做幂等重放；重放命中先于 If-Match 检查，返回原状态码和 data，requestId 为本次请求 ID。只读 C10 检索和 I05 图文导出不要求幂等键；它们仍校验权限与 CSRF。
- GET 列表采用 `limit=20`、最大 100、`cursor`，按 `(createdAt,id)` 排序；不接受任意 SQL 排序表达式。

成功：

```json
{"data":{"id":"<uuid>"},"requestId":"<request-uuid>"}
```

分页：

```json
{"data":{"items":[],"nextCursor":null},"requestId":"<request-uuid>"}
```

失败：

```json
{"error":{"code":"REVISION_CONFLICT","message":"内容已变化，请重新载入","details":{"currentRevision":4},"retryable":false},"requestId":"<request-uuid>"}
```

示例中的 `<uuid>` 为占位符，不是可提交的实际 ID。未特别说明，成功读/改为 200，创建为 201，异步启动为 202。

## 2. 公共数据结构

### 2.1 TaskBrief

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| topicName、background | string | 发布前均非空。 |
| subject、grade | string | 发布前必填。 |
| learningGoals | string[] | 发布前至少一项。 |
| coreQuestion | string | 发布前必填。 |
| isHistoricalTopic | boolean | 发布前必填。 |
| timeAnchor | TimeAnchor/null | 历史主题发布前必填；与 RoleCard 相同。 |
| region | string/null | 主题需要限定地域时必填，虚拟角色不得自称代表所有群体。 |
| roleType | real_historical / fictional_composite | 发布前必填。 |
| roleName | string/null | 可在生成前为空，发布前与 RoleCard.name 一致。 |
| materialPolicy | object | `{externalKnowledgeAllowed:boolean,externalKnowledgeScope:string}`；默认禁止外部知识，允许时范围非空。 |
| restrictions | object | `{maxTurns:integer,suggestedMinutes:integer,deadlineAt:datetime\|null,difficulty:string,forbiddenContent:string[]}`；maxTurns、suggestedMinutes>0。 |
| expectedOutcome | string | 发布前必填。 |
| confirmedFields | string[] | 教师已确认字段路径，限定白名单；用于不重复澄清。 |

`TimeAnchor={value:string,precision:"year"|"month"|"day"}`；value 分别使用 YYYY、YYYY-MM、YYYY-MM-DD。年粒度不能自动判断年内事件先后，依赖具体月份的回答需进一步澄清或说明无法确认，不能默认为年末。

草稿允许不完整；业务发布必填不代表教师必须手工输入。默认值和模型生成可补齐，无法可靠推定的信息才返回 `missingFields` 及 `nextQuestions`，最多三个必要问题。外部知识范围不等于自动联网授权；首版只有上传资料可生成可定位的资料引用。真实历史人物必须按历史主题设置时间锚点。

### 2.2 RoleCard

| 字段 | 类型与约束 |
| --- | --- |
| roleId | UUID，正式保存时由服务端确定；修改保留原 ID，复制为新版本时分配新 ID，不能由模型指定。 |
| name | string。 |
| roleType | real_historical / fictional_composite。 |
| identityDescription | string。 |
| historicalPeriod | string。 |
| timeAnchor | TimeAnchor/null；与当前 TaskBrief 一致，历史主题必填。非历史主题允许 null，并明确非历史情境。 |
| region、socialGroup | string；不适用时明确写“未限定”，不能遗漏字段。 |
| position | string。 |
| goals、concerns | string[]。 |
| relationships | `{target:string,description:string}[]`，只描述背景人物关系。 |
| knownFacts | `{text:string,evidenceIds:UUID[],origin:"material"\|"teacher"}[]`。 |
| unknownFacts | string[]。 |
| sourceIds | UUID[]；必须是本版本关联的 ready Source 子集，允许空数组。 |
| disputedClaims | `{text:string,evidenceIds:UUID[],limitation:string}[]`。 |
| speechStyle、openingMessage | string。 |
| recommendedQuestions | string[]，1～3 项。 |
| learningDimension | string。 |
| forbiddenBehaviors | string[]，至少包含不编造、不越界、不代写等已确认约束。 |

`QuestionPlan` 为 `{question:string,dimension:string,purpose:string}[]`，发布前至少一项。问题链与角色卡共同校验和发布。

`RoleCardInput` 为不含 roleId 的 RoleCard，用于教师输入和模型生成候选；服务端补 roleId 后形成正式 RoleCard。非历史主题的 historicalPeriod 可明确填写“非历史情境”，不省略字段。

### 2.3 Version、Source 与 Evidence

`Version`：`id,taskId,versionNo,revision,status,teachingIntent,brief,questionPlan,roleCard,sourceIds,manualFields,generationMeta,validationStatus,validatedRevision,previewRevision,createdAt,publishedAt,missingFields,nextQuestions`。status=draft/published；validationStatus=stale/valid/invalid。manualFields 为服务端维护的人工编辑路径；generationMeta=`{appliedRunId,appliedRevision,assumptions:string[]}`，未生成时为空对象。草稿无角色时 roleCard=null；发布前必须存在。previewRevision 保留字段名但改为自动五类检查通过的 revision，不再要求五次人工评阅。只有教师可读完整 Version；技术字段用于程序控制，不直接展示。

`Source`：`id,taskId,fileName,fileType,byteSize,sha256,status,pageCount,parseError,warnings,createdAt`。fileType=pdf/txt；status=uploaded/parsing/ready/failed；不返回服务器存储路径。

`Evidence`：`id,sourceId,text,pageNo,paragraphNo,startLine,endLine,disputed,sourceLabel`。PDF pageNo 从 1 开始；TXT 行号从 1 开始且含端点。坐标不适用时为 null。

### 2.4 Message、Citation 与 Run

`AnswerBlock`：`{blockIndex:integer,type:"fact"|"opinion"|"inference"|"unknown",text:string,evidenceIds:UUID[]}`；blockIndex 从 0 连续递增。fact 必须有被支持的 evidenceIds，不能只给来源名称；无可核验来源时不能标为 fact。

`Citation`：`{id,messageId,blockIndex,evidenceId,sourceId,fileName,pageNo,startLine,endLine,paragraphNo,quote}`。全部定位字段由后端从 Evidence 取得。

`Message`：`id,sessionId,seq,speaker,status,text,blocks,citations,runId,supersedesMessageId,meta,createdAt`。speaker=user/assistant；status=pending/partial/complete/discarded。助手 meta 对外包含 `roleId,roleType,timeAnchor,followUpQuestions,phase,memorySummary`，只输出适合学生阅读的摘要。

内部 `Run`：`id,kind,status,sessionId,versionId,versionRevision,inputMessageId,outputMessageId,retryOfRunId,stepCount,maxSteps,cancelRequestedAt,terminalReason,result,error,createdAt,finishedAt`。kind=parse_material/role_generate/role_validate/plan_generate/publish_preflight/chat/summary/learning_report；status=running/waiting_confirmation/completed/failed/cancelled。

公共 `RunView`：`id,kind,status,displayMessage,sessionId,versionId,result,error,createdAt,finishedAt`，不含预算、步骤、原始检查结果或隐藏提示。所有下文对外 Run 响应实际序列化为 RunView。result 按业务返回方案、报告 ID 或准备状态；error 仅含 code、可读 message、retryable。学生不得得到教师候选或内部安全记录。

### 2.5 可选笔记与历史成果

`Note`：`id,sessionId,messageId,blockIndex,originalView,type,evidenceIds,judgment,credibility,limitations,rowVersion,createdAt,updatedAt`。创建只需 messageId/blockIndex，judgment/limitations 默认空，credibility 默认 unassessed。旧字段保留兼容，界面只提供可选“补充一句想法”。

`LegacySubmission`：`id,sessionId,status,content,rowVersion,submittedAt,createdAt,updatedAt`；content 保留旧 conclusion、roleView、supportingEvidenceIds、counterarguments、viewChanges、unresolvedQuestions、reflection。只读展示“之前提交的成果”，不以这些字段是否非空阻止本版结束探究，也不把旧成果静默改成 AI 报告。

### 2.6 学习事件、自动报告与更正

`LearningEvent`：`id,sessionId,type,sourceId,messageId,value,rowVersion,createdAt,updatedAt`。

- type=source_open：只填 sourceId，读取本人已展示引用的原文成功后记录。同会话同 Source 一条，不按点击次数累加。
- type=stance：只填已完成、非开场助手回答的 messageId 和 value；value=need_more_evidence/agree_for_now/alternative_explanation，对应“需要更多证据/暂时赞同/有不同解释”。同会话同回答一条，改选更新当前值。两类事件均由当前学生身份记录，教师不能代写。
- ended 后不能新增或修改事件。sourceTracking=complete/partial/unavailable 表示来源行为采集覆盖范围；旧记录缺少采集时不能返回伪造点击。

`ReportContent` 为模型经校验后的输出：

```json
{
  "summary": {"text": "对学生已表达内容的概括", "messageIds": ["<student-message-id>"]},
  "findings": [{"kind": "student_judgment", "text": "已表达的判断", "messageIds": ["<student-message-id>"], "evidenceIds": []}],
  "signals": [{"messageId": "<student-message-id>", "quote": "学生原话", "tags": ["judgment"]}],
  "missingAspects": ["尚未明确说明反例"],
  "nextSteps": ["可以再对照一段原文"]
}
```

findings.kind=student_judgment/evidence_seeking/counterargument/view_change/reflection/unresolved/role_view；除 role_view 仅引用助手消息外，其余必须关联学生原话，view_change 要能对应前后表达。signals 每个学生 messageId 最多一项，tags 从 evidence_seeking/judgment/reflection 中去重选取。quote 必须是该学生消息的逐字片段；evidenceIds 必须来自该会话已展示引用。summary 不得把角色观点写成学生观点；缺失信息留在 missingAspects，不生成不存在的立场变化。报告先经结构、归属、引用及语义检查才可 ready。

`LearningReport`：`id,sessionId,reportNo,kind,status,inputRevision,generatedAt,content,metrics,sourceTracking`；kind=live/final；status=queued/generating/ready/failed/superseded。content 仅 ready 时有值；metrics 由程序根据固定输入快照和有效 signals 计算，模型不得写数值。运行预算、原始快照与诊断错误不返回给师生。

`ReportMetrics`：`expressionCount,evidenceSeekingCount,sourceViewCount,judgmentCount,reflectionCount`。表达数来自学生消息；寻找依据/反思来自对应标签的不同消息；判断数为判断消息数加当前 stance 数；来源数为不同 Source 数。没有 ready 报告时语义类计数为 null，来源采集不可用时 sourceViewCount=null；0 仅表示已覆盖范围内确实没有记录。

`ReportCorrection`：`id,sessionId,reportId,authorId,text,createdAt`。text 去空白后 1～2000 字；绑定同一学生会话的一份 ready 报告，追加而不改写旧内容，不进入对话行为计数。

`ReportEnvelope`：`sessionId,sessionStatus,currentLearningRevision,currentReport,latestReadyReport,freshness,corrections,nextCorrectionCursor,legacySubmission`。freshness=empty/updating/current/failed；currentReport 是最新应完成的报告（结束后优先 final），latestReadyReport 可为旧 live 结果供等待时阅读。corrections 首批最多 50 条，H12 继续分页；legacySubmission 可空。报告原话通过 F03 或 I04 回查。

### 2.7 图表统计范围与一致性

`ReportScope`：scope=latest/all/version，默认 latest；仅 version 时必须且允许携带 versionId，属于当前任务且已发布。state=all/active/ended 只筛选学生列表，顶部指标、课堂小结和行为图仍针对整个发布范围。

教师聚合返回 asOf、aggregateToken、coverage。aggregateToken 是服务端对范围、会话学习版本、选用的 ready 报告 ID、当前事件和更正版本的规范摘要哈希；不是授权凭证。I04/I05 重新核对，变化返回 REPORT_CHANGED，客户端刷新 I01 后重试。快照读取使用短事务，不能在其中调用模型。

coverage 至少包含 totalSessions、readyReportSessions、currentReportSessions、sourceTrackedSessions、partialSourceSessions、unavailableSourceSessions。语义指标仅累加已有报告结果，可能滞后时展示“部分内容正在整理”；sourceViewCount 对未采集会话不补 0，返回覆盖数。无任何可用依据的聚合指标为 null。预览/自动检查全部排除，当前授权撤销不删除教师历史统计。

归档不物理删除任何表或文件；取消该任务活跃 Run，冻结写入。教师可通过任务列表恢复；B09 重复请求幂等。手工 B07/D03 修改的字段路径由服务端记入 manualFields，默认值与 AI 字段不误标成人工编辑；客户端不能直接写 manualFields 或 generationMeta。

## 5. C：资料、证据与原文

| ID | 方法与路径 | 请求 | 返回 |
| --- | --- | --- | --- |
| C01 | POST `/versions/{versionId}/sources` | multipart `file`；If-Match；owner/draft | 202 `{source:Source,run:Run,revision}`。关联资料使 revision+1，后台解析。 |
| C02 | GET `/versions/{versionId}/sources` | owner | Source 列表；不分页，首版按任务文件限额控制。 |
| C03 | POST `/versions/{versionId}/source-links` | `{sourceId}` + If-Match | `{sourceId,revision}`；仅复用同任务 ready Source。 |
| C04 | DELETE `/versions/{versionId}/sources/{sourceId}` | If-Match | `{detached:true,revision}`；只解除 draft 关联，保留原文件与历史版本。 |
| C05 | GET `/sources/{sourceId}` | owner；学生需本人会话已引用 | Source 元数据。 |
| C06 | GET `/sources/{sourceId}/evidence` | owner，分页 | Evidence 列表。学生不允许批量枚举资料片段。 |
| C07 | GET `/evidence/{evidenceId}` | owner；学生需本人已显示引用 | Evidence + 可访问的 sourceId。 |
| C08 | GET `/sources/{sourceId}/file` | 同 C05；可带 Range | 原始文件，200/206；不满足范围416。Content-Disposition 使用安全文件名，不返回内部路径。 |
| C09 | GET `/sources/{sourceId}/text` | 同 C05，TXT；`startLine=1&limit=200` | `{sourceId,totalLines,startLine,lines:[string]}`，支持分页查看原文。非TXT返回422。 |
| C10 | POST `/versions/{versionId}/evidence-search` | `{query,topK:6}`；owner | `{evidence:[Evidence],insufficientEvidence:boolean}`，用于教师测试；不开放给学生任意检索。 |

每版本默认最多 10 份资料，文件默认不超过 10 MiB、PDF 不超过 100 页；作为服务端配置统一校验。解析完成时 Source/Evidence 一次性提交；如果仍关联某个 draft，该 draft revision 再递增并失效校验。解析只依赖不可变文件，因此不因教师同期编辑其他字段丢弃解析结果；角色生成/校验则必须检查启动 revision。

解析错误：`UNSUPPORTED_FILE_TYPE`、`FILE_TOO_LARGE`、`PDF_ENCRYPTED`、`OCR_REQUIRED`、`TEXT_DECODE_FAILED`、`PARSE_TIMEOUT`。ready Source 不允许重新解析覆盖；替换上传新 Source。failed Source 可通过重新上传创建新的解析运行。

| D07 | POST `/versions/{versionId}/preflights` | owner/draft；空对象 + If-Match；前端自动调用 | 202 Run；相同 revision/内容/规则已有 running 或有效终态时 200 复用。完成只返回 PublishReadiness。 |
| D08 | POST `/versions/{versionId}/plan-generations` | owner/draft；`{confirmationId?:UUID}` + If-Match；使用已保存 teachingIntent | 202 Run(kind=plan_generate)；成功应用后 result=`{version:Version,undoAvailable:true}`。 |
| D09 | POST `/versions/{versionId}/plan-generations/{runId}/undo` | owner/draft；空对象 + If-Match | 新 Version；仅当当前 revision 等于该次 appliedRevision 且未撤销时恢复。 |

D07 不接收客户端声明“检查通过”。内部必须完整且不重复覆盖 identity/future_information/private_motives/viewpoint_conflict/prompt_injection。result=pass/fail/not_applicable；只有非历史主题的 future_information 允许 not_applicable 并记录原因。成功在当前 revision 保存 role_validation 与 publish_preflight 记录和两个通过标记；失败返回可操作提示。原 `/preview-review` 人工逐项写接口退役，返回 410 LEGACY_WRITE_DISABLED。

自动检查结果必须关联 revision、contentHash、checkVersion。编辑/解析后缓存失效；过期 Run 不修改新草稿。重跑技术失败用新幂等键调用 D07；结果存在确定性阻断时应先修正内容，不无限自动重试。D06 自由试聊不计学生数据，也不要求教师完成五轮测试。

D08 在事务外生成 TaskBrief、RoleCard、QuestionPlan 与 assumptions，不更换已关联资料。未指定的业务信息允许生成，可靠性不足时记录缺失项。明确提供的学科/年级和未授权覆盖的人工字段必须保持。存在需替换的人工字段时，先通过 E01 replace_plan 确认其路径；首次空草稿不额外确认。回写事务重验启动 revision/确认期限/来源集合，保存 beforeSnapshot 审计和 appliedRevision，递增 revision 并失效检查；过期结果不覆盖人工编辑。无法完整补齐时仍可保存安全的草稿，并通过必要问题补充，不能伪造历史时间。

D09 从本次应用审计恢复生成前的 brief、RoleCard、问题链和字段来源，保留教学意图和原资料。revision 递增而非回退；有后续编辑、已撤销或已发布时返回 UNDO_NOT_AVAILABLE。成功后自动重新执行 D07。单独完善角色的 D01/D04 路径继续保留。

角色生成完成结果：

```json
{"candidate":{"roleCard":{},"recommendationReason":"该角色与本任务探究目标的关系","questionPlan":[],"coverage":{"coveredGoals":[],"gaps":[],"disputes":[],"risks":[]}},"candidateHash":"<sha256>","baseRevision":5}
```

此处空对象仅示意字段结构，实际 candidate.roleCard 必须满足 RoleCardInput；recommendationReason 为非空 string，coverage 四个字段均为 string[]。Run.status=waiting_confirmation；确认应用前不修改当前角色卡。若草稿 revision 已变，应用返回409 `CANDIDATE_STALE`；重新生成或教师手工合并。

手工修改角色卡时，若 name/roleType/timeAnchor 与 brief 不一致，可保存草稿但标为 invalid，必须修正后才通过发布预检。

## 7. E：确认与发布

### E01 POST `/versions/{versionId}/confirmations`

owner + If-Match + Idempotency-Key。请求：

```json
{"action":"publish_version","confirmed":true,"taskRevision":2,"payload":{"studentIds":["<student-uuid>"]}}
```

action=apply_role_candidate 时 payload=`{runId,candidateHash}`；action=archive_task 时 payload=`{}`；action=replace_plan 时 payload=`{intentHash,overwrittenFields:string[]}`，路径白名单及当前内容由服务端核对。服务端校验目标、版本、用户和内容，生成规范化 payloadHash；confirmed 必须 true。返回201：

```json
{"data":{"confirmationId":"<uuid>","action":"publish_version","versionRevision":5,"expiresAt":"2026-11-03T05:30:00Z"},"requestId":"<uuid>"}
```

确认默认有效30分钟。candidateHash 需与服务端 Run 结果一致；发布名单去重、排序并校验均为学生。不得因收到模型文本“老师已同意”而创建确认记录。

发布和候选应用均绑定创建确认时的 versionRevision 和 taskRevision。archive_task 只在实际归档时核对 taskId/taskRevision、用户、期限和动作；URL 的版本用于创建时定位任务，不因随后草稿内容变化而拒绝归档。

### E02 GET `/versions/{versionId}/publish-check`

owner。返回 `PublishReadiness={ready,state,revision,taskRevision,contentHash,blockingIssues:[{field?,message}],nextQuestions:string[]}`，state=preparing/needs_input/ready/unavailable；nextQuestions 最多 3 项。只读取字段及已完成检查，不启动模型、不发布、不创建确认；不返回五类内部检查卡片。界面合并去重后只展示需要补充什么，preparing 显示“正在准备方案”。

### E03 POST `/versions/{versionId}/publish`

owner + If-Match + Idempotency-Key。请求 `{confirmationId}`；名单读取确认快照，不接受额外覆盖名单。

返回 `{taskId,versionId,versionNo,status:"published",publishedAt,taskRevision}`。短事务重验当前字段、来源、自动检查的 revision/hash/checkVersion 与 Confirmation，不能仅相信旧 ready=true；事务内不调用模型，自动检查缺失则由前端后台调用 D07 后再次确认当前内容。

错误包括 `VALIDATION_REQUIRED`、`PREFLIGHT_REQUIRED`、`SOURCE_NOT_READY`、`CONFIRMATION_REQUIRED`、`CONFIRMATION_EXPIRED`、`CONFIRMATION_STALE`。成功后版本内容不可变；幂等重放返回同一个发布结果。

### 9.1 SSE 格式

```text
id: 3
event: answer.block
data: {"runId":"<uuid>","seq":3,"messageId":"<uuid>","block":{"blockIndex":0,"type":"fact","text":"……","evidenceIds":["<uuid>"]},"citations":[]}

id: 4
event: run.completed
data: {"runId":"<uuid>","seq":4,"messageId":"<uuid>","completedTurns":1}

```

事实块实际必须包含已核验引用；这里省略 citations 内容只示意事件格式。

| event | data 核心字段 | 持久化与展示 |
| --- | --- | --- |
| run.started | runId、seq、kind、status | 创建Run时保存。 |
| run.progress | runId、seq、phase、displayMessage | phase=preparing/answering/reporting；前端只显示“正在准备回答 / 正在回答 / 正在整理报告”，不显示技术检查阶段。 |
| answer.block | runId、seq、messageId、block、citations | 先保存合格消息块和引用，再发事件；客户端按seq去重。 |
| answer.meta | runId、seq、messageId、followUpQuestions、phase、memorySummary | 已核验的追问和面向学生的摘要，不泄露内部知识边界。 |
| run.waiting_confirmation | runId、seq、resultSummary | 教师候选生成完毕，需要人工应用。 |
| run.completed | runId、seq、messageId?、completedTurns?、result? | Run与消息终态提交后发送，关闭流。 |
| run.failed | runId、seq、code、message、retryable、partialMessageId? | 终态；部分内容保留partial，无块时discarded。 |
| run.cancelled | runId、seq、reason、partialMessageId? | 终态，停止后续写块。 |

每15秒可发送不入库的 `: heartbeat` 注释。连接建立前的鉴权失败返回普通JSON错误；流已建立后使用终态事件，不能再尝试改变HTTP状态码。waiting_confirmation也结束当前流；后续应用结果通过GET Run或重新订阅取得。

afterSeq 为调用方最后成功处理的序号；从大于该序号的事件开始，终态Run重放完即可关闭。禁止学生重放他人或教师预览事件。每批重放/推送和心跳前重查当前授权；撤权或任务归档后关闭连接，不再发送业务内容。原始核验候选和内部风险细节不放到公开事件中。

### 9.2 手动重试约束

G04 仅重试 chat；报告使用 H11，预检使用 D07。新Run.retryOfRunId 指向原Run，inputMessageId复用原用户消息，新助手消息supersedesMessageId指向该问题最近一次助手消息。retry 必须针对该问题最新的失败/取消 Run；已被重试的旧 Run 返回 RETRY_NOT_ALLOWED，避免分叉。已存在新问题、已成功、会话ended、达到轮次/截止时间、归档、撤销授权或有活跃 chat/summary Run 时返回409/404。learning_report 不占交互锁；全部模型调用仍受全局容量约束。不会把retryOf链自动无限重试。

- I03 results 为 `{roleConsistency?,sourceAccuracy?,knowledgeBoundary?,inquiryDepth?}`；值 pass/fail/not_applicable，至少一项或一条 note，note 最多2000字。页面使用“角色回答是否贴合人物”等教学用语，不暴露评测代码。

内部 ReviewRecord 继续保存 role_validation/answer_check/preview_review/publish_preflight/evaluation/business_audit，version/revision、Run、message/block 定位和 evidenceAssessments。preview_review 仅兼容旧数据；I02 不直接序列化 resultJson 或业务审计。成功拦截可转为教学讨论提示，不作为学生错误或角色违规。

I05 导出整个所选发布范围，不受学生列表分页或进度筛选影响；明确写出范围和生成时点。若有未完成报告，显示整理中/失败和可用旧摘要，不临时调用模型、不伪造空白结论。HTML 内嵌样式，所有文本转义，不含脚本、运行日志、内部 ID 列表、令牌或其他任务数据；引用变成文件名、位置和原文摘录，不能嵌入未经授权的文件链接。老师查看和导出都不写学生学习事件。

## 12. 六个内部工具契约

内部工具不是可绕过权限的HTTP公共接口。Context由后端构造：`{actorId,taskId,versionId,revision,sessionId?,runId?,remainingSteps,deadline}`，不得由模型自行覆盖。

统一返回 `{ok:boolean,result:object|null,error:{code,message,retryable}|null}`；读写属性用于编排和确认，不代表只读工具可以越权读取。

| 工具 | 输入Schema要点 | 输出Schema要点 | 属性 | 单次建议超时/自动重试 |
| --- | --- | --- | --- | --- |
| parse_material | `{sourceId}` + context | `{sourceId,status,evidenceIds,warnings}` | 写入 | 60秒；最多2次，格式错误不重试。 |
| retrieve_evidence | `{query,topK}` + snapshot sourceIds | `{evidence,insufficientEvidence}` | 只读 | 5秒；最多2次，权限错误不重试。 |
| generate_role_cards | `{brief,evidence,existingRoleCard?}` | `{roleCard:RoleCardInput,recommendationReason,questionPlan,coverage}` | 产生候选，不直接覆盖 | 30秒/次；有限修复与重试共用步骤预算。 |
| check_role_consistency | `{mode:"role"\|"answer",roleCard,questionPlan?,question?,blocks?,evidence}` | `{passed,issues:[{code,severity,blockIndex?,message,evidenceIds}]}` | 只读判断 | 30秒/次；最多2次。 |
| save_task_draft | `{versionId,expectedRevision,changes,confirmationId?}` | `{revision,validationStatus,missingFields,nextQuestions}` | 写入 | 5秒；冲突不重试，应用候选覆盖人工内容需确认。 |
| publish_task | `{versionId,expectedRevision,confirmationId,idempotencyKey}` | `{taskId,versionId,publishedAt,taskRevision}` | 高风险写入 | 5秒；不得盲重试，按幂等记录查结果。 |

自动重试是首次加最多两次；修复调用也计入Run.maxSteps和总时限。同步发布/保存没有LLM决策，不强制生成一个长生命周期Run：按动作使用确认/幂等规则，所有内容变更写 business_audit；普通教师 PATCH 保存无需额外确认。parse_material、retrieve_evidence 和核验无需用户二次确认；generate_role_cards 仍只产候选；plan_generate 工作流按明确的首次生成/替换授权调用保存工具，单独角色候选应用与发布仍须确认。教学方案、自动预检和学习报告是显式服务工作流，不增加通用工具平台。

## 13. 错误码

| HTTP | code | 处理 |
| --- | --- | --- |
| 401 | UNAUTHENTICATED | 重新登录。 |
| 403 | FORBIDDEN / CSRF_FAILED | 拒绝，不重试。 |
| 404 | NOT_FOUND | 对象不存在或不可见。 |
| 409 | DRAFT_EXISTS / VERSION_IMMUTABLE / SESSION_ENDED / ACTIVE_RUN_EXISTS | 按当前状态处理。 |
| 409 | IDEMPOTENCY_CONFLICT / CANDIDATE_STALE / UNDO_NOT_AVAILABLE | 换新业务请求或重新生成，不能自动覆盖。 |
| 409 | VALIDATION_REQUIRED / PREFLIGHT_REQUIRED / SOURCE_NOT_READY | 前端自动安排检查；只显示具体待补充内容。 |
| 409 | EVENT_CONFLICT / REPORT_CHANGED / REPORT_SUPERSEDED | 重新读取事件或报告范围，不能覆盖旧版本或混用统计快照。 |
| 410 | LEGACY_WRITE_DISABLED / INTERNAL_DIAGNOSTIC_ONLY | 不再调用旧成果写入、人工检查或步骤接口。 |
| 409 | CONFIRMATION_REQUIRED / CONFIRMATION_EXPIRED / CONFIRMATION_STALE | 人工重新确认当前内容。 |
| 409 | TURN_LIMIT_REACHED / RETRY_NOT_ALLOWED / DEADLINE_REACHED | 不启动模型。 |
| 412 | REVISION_CONFLICT | 重载并人工合并。 |
| 413 / 415 | FILE_TOO_LARGE / SOURCE_LIMIT_REACHED / UNSUPPORTED_FILE_TYPE | 修改输入。 |
| 422 | VALIDATION_ERROR / EMPTY_EXPLORATION / INVALID_REPORT_REFERENCE / OCR_REQUIRED / PDF_ENCRYPTED / TEXT_DECODE_FAILED | 显示可读的补充提示；空探究先进行一次表达。 |
| 428 | PRECONDITION_REQUIRED | 补If-Match等并发条件。 |
| 429 | CAPACITY_LIMIT | 稍后重试，附Retry-After。 |
| 502 / 504 | MODEL_UNAVAILABLE / MODEL_TIMEOUT / PARSE_TIMEOUT | 若异步已接收则通过run.failed返回，不再改HTTP。 |

仅运行终态原因：`ANSWER_REJECTED,REPORT_REJECTED,STEP_LIMIT_REACHED,RUN_TIMEOUT,PROCESS_INTERRUPTED,USER_CANCELLED,ACCESS_REVOKED,STALE_REVISION`。这些不直接等同于请求HTTP状态；G01仍以200返回该Run及其error。

## 14. 联调顺序与检查

1. A01 → B01 → B07：登录、教学意图保存、默认字段与 revision 冲突。
2. C01 → G01/G02 → C07/C08/C09：资料解析与引用定位；新资料解析完成使旧自动检查失效。
