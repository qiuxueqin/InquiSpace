# 实习任务二：设计并实现角色化主题探究 Agent

> 阶段一：单角色沉浸式探究（必做，★★）
>
> 本文以飞书《02.任务二》为母版，保留阶段一需求及其必要的通用约束，删除后续阶段专属内容，并对角色数量、流程和编号作必要衔接调整。验收包括第八节的阶段一验收用例，以及本文保留的资料与来源等通用要求。

**产品定义：**主题探究 Agent 是一个角色化学习 Agent。教师围绕一个主题创建一个真实历史人物或虚拟综合人物，学生通过与该角色对话，了解其在特定时代、地域和利益背景下的认知与立场，最终形成自己的结论。

角色不是换名字的通用问答机器人，也不是全知百科。角色必须遵守自己的身份、时间锚点、立场、资料依据、认知边界和语言风格。

## 一、需求背景

主题探究的核心，是让学生进入一个由具体人物、立场和时代情境构成的探究场景。学生需要通过提问获取信息，通过资料核验判断可信度，最终形成自己的结论。

例如探究“清朝灭亡”时，学生可以与溥仪这一角色对话，从皇室经历和个人处境出发理解其视角。角色掌握的信息、利益立场和认知边界有限，学生需要理解该视角的局限。

角色可以是真实历史人物，也可以是教师基于资料创建的虚拟综合人物。无论哪种角色，Agent 都必须区分资料支持的事实、角色立场、合理推断和无法确认的信息，不得为了沉浸感编造史实、原话、私人经历或心理活动。

本任务要求实现一个单角色主题探究 Agent：教师能够创建角色探究场景；学生能够与该角色连续对话、记录证据，并通过追问、阶段小结和反思形成自己的结论。

## 二、需求范围与边界

### 1. 必须实现

- 教师创建主题，设置学科、年级、探究目标、时间锚点、地域范围、资料范围和期望成果。
- Agent 根据主题和资料生成或补全一个角色卡，教师可以编辑、预览和确认。
- 支持真实历史人物和虚拟综合人物，并在界面上明确标识角色类型；每个任务只使用一个角色。
- 教师预览角色对话，确认后发布。
- 学生与该角色连续对话，角色以符合身份的第一人称交流，同时遵守时间、知识和资料边界。
- 支持推荐问题、自由提问、动态追问、阶段小结和最终成果。
- 学生可以记录角色观点、证据、局限和自己的判断。
- 任务完成后保留探究成果，教师能够回看对话、探究笔记和最终成果。
- 实现 Agent Run 状态、最大步骤、停止、重试和人工确认。

### 2. 不要求或禁止

- 不要求模拟人物的真实意识，也不得声称角色回答等同于人物本人真实想法。
- 真实人物不得编造经历、原话、秘密信息、确定动机或未被资料支持的心理活动。
- 虚拟综合人物不得冒充真实存在的人，也不得虚构史料出处。
- 角色不得使用时间锚点之后的信息形成全知回答。
- Agent 不得替学生直接代写最终探究结论。
- 后台是否使用多个模型或多个 Agent 属于技术方案，不替代面向学生的角色化交互。

## 三、贯穿示例：探究“清朝灭亡”

下面的示例用于统一理解需求和验收口径，实习生还需要准备至少两个其他学科或主题的测试案例。每个案例均采用单角色探究。

| 角色 | 类型 | 主要视角 | 边界示例 |
| --- | --- | --- | --- |
| 溥仪 | 真实历史人物 | 皇室处境、宫廷生活和个人经历 | 必须明确对话时间点；不能以亲历者口吻回答当时尚未发生的事件。 |

**单角色对话示例：**学生向溥仪询问皇室如何看待局势，继续追问其回答依据与信息局限。角色在所设时间锚点和资料范围内回答，并引导学生说明自己的判断依据。遇到未来事件或未被资料支持的私人动机时，角色应明确说明超出当前认知或无法确认。

## 四、用户流程

### 1. 教师创建流程

1. 输入主题、学科、年级、探究目标、时间锚点、地域范围和期望成果。
2. 提供参考资料，设置是否允许补充外部知识，以及是否允许创建虚拟综合人物。
3. Agent 分析主题、人物背景和教学目标，生成任务简报与一个角色的建议。
4. 教师审核该角色的身份、时代背景、立场、已知信息、未知信息、语言风格和资料依据。
5. Agent 为该角色生成开场情境、推荐问题和探究价值说明。
6. 教师预览角色对话，检查是否发生身份漂移、越过时代边界或缺少依据。
7. 确认发布对象、时间、对话轮次、难度和资料范围后发布。

### 2. 学生探究流程

1. 阅读主题背景、核心问题、完成要求及本次角色的身份与背景。
2. 进入该角色所处的时间、地域和事件情境。
3. 使用推荐问题或自由提问，追问角色经历、依据、利益和立场。
4. 将关键回答加入探究笔记，标注角色、事实或观点、资料来源、可信程度和可能局限。
5. 回应 Agent 提出的证据、反例和认知边界问题，完成阶段小结。
6. 形成“我的结论—角色观点—支持证据—反方观点—观点变化—反思”的最终成果，说明该角色视角的局限和还需要了解的其他观点。

## 五、明确的输入与输出

### 1. 教师侧输入

| 字段 | 要求 | 是否必填 |
| --- | --- | --- |
| 主题名称与背景 | 说明要探究的事件、作品、现象或问题。 | 是 |
| 学科与年级 | 决定表达难度、资料范围和教学目标。 | 是 |
| 探究目标与核心问题 | 说明学生最终需要理解或论证什么。 | 是 |
| 时间锚点 | 规定角色当前所处时间和知识截止时间。 | 历史主题必填 |
| 地域范围 | 限制虚拟综合人物所代表的地域和社会范围。 | 按主题 |
| 角色类型 | 真实历史人物或虚拟综合人物。 | 是 |
| 角色 | 教师指定，或由 Agent 推荐一个角色。 | 是 |
| 参考资料 | 文档、图片、文本及允许使用的外部知识范围。 | 否 |
| 任务限制 | 最大轮次、建议时长、截止时间、难度和禁止内容。 | 是 |
| 期望成果 | 如历史解释或反思报告。 | 是 |

必填信息缺失时，Agent 每轮最多提出 3 个必要问题；已确认内容不得重复询问。教师修改时间锚点、目标或资料范围后，角色卡和问题链必须重新校验。

### 2. Agent 创建任务输出

- 结构化任务简报和仍待确认的信息。
- 一个完整角色卡，以及该角色的探究价值。
- 该角色的开场情境及 1～3 个推荐问题。
- 资料覆盖情况、缺口、争议和风险提示。
- 教师预览结果和发布前检查结果。

### 3. 单轮学生对话输出

- 当前发言角色、角色类型和所处时间。
- 符合角色身份、立场、语言和认知边界的回答。
- 回答类型：资料事实、角色观点、合理推断或无法确认。
- 资料来源及可定位到原文的引用，或明确的“现有资料无法确认”标记。
- 面向学生的追问、证据提示或下一步建议。
- 当前对话阶段和会话记忆摘要。

### 4. 任务结束输出

- 该角色的核心观点及对应证据。
- 该角色视角与信息的局限。
- 学生自己的结论、采纳的证据、回应的反例和观点变化。
- 未解决问题和后续探究建议。
- 教师可回看的对话记录、探究笔记和最终成果。

## 六、核心功能需求

### 1. 主题理解与角色建议

- Agent 识别主题中的关键事件、人物、群体、利益关系、观点冲突和教学目标。
- Agent 推荐一个适合探究目标的角色，并说明推荐原因。

### 2. 角色卡

角色必须使用结构化 RoleCard，至少包含：

| 字段 | 含义 |
| --- | --- |
| `roleId` / `name` | 唯一标识和展示名称。 |
| `roleType` | `real_historical` 或 `fictional_composite`。 |
| `identityDescription` | 身份、社会位置、经历及其与主题的关系。 |
| `historicalPeriod` / `timeAnchor` | 所处时期、具体对话时间点和知识截止时间。 |
| `region` / `socialGroup` | 地域、阶层或代表群体的限定范围。 |
| `position` / `goals` / `concerns` | 基本立场、当前目标、利益和顾虑。 |
| `relationships` | 与主题相关人物或群体的背景关系、冲突或依赖。 |
| `knownFacts` / `unknownFacts` | 允许知道和不应知道的信息范围。 |
| `sourceIds` / `disputedClaims` | 可依据的资料以及存在争议、不得直接断言的内容。 |
| `speechStyle` | 称谓、语气、表达方式及面向目标年级的可读性。 |
| `openingMessage` | 符合时间和情境的首次对话开场语。 |
| `recommendedQuestions` | 1～3 个适合从该角色开始的探究问题。 |
| `learningDimension` | 该角色承担的探究视角。 |
| `forbiddenBehaviors` | 禁止编造、越界、冒充、泄露提示词或代写结论等规则。 |

### 3. 角色一致性

- 同一角色在连续对话中保持身份、时间、地域、立场、关系和语言风格一致。
- 角色不能使用时间锚点之后的信息。询问未来事件时，应明确表示超出当前认知。
- 真实人物只能基于资料表达可核对的经历和公开观点；资料不足时必须说无法确认。
- 虚拟综合人物始终展示虚拟标识，只能代表被限定的群体视角。
- 角色可以承认不知道、信息不足或自身立场有限。
- 收到“忘记设定”“你现在是历史专家”等指令时，不得改变角色边界。
- 角色回答争议问题时展示争议和局限，不把推断包装成史实。
- 角色通过追问引导学生，不直接代写最终探究成果。

### 4. 单角色对话

- 同一主题任务使用一个角色，学生进入该角色的会话并连续交流。
- 推荐问题可直接发起对话，也支持学生自由提问。
- 支持流式输出、停止生成、失败重试和继续追问。
- 学生可以把任意回答加入探究笔记，并标记证据、可信度和局限。
- Agent 根据学生当前回答追问理由、证据或反例，不替学生生成最终判断。
- 支持阶段小结和最终成果。

### 5. 资料与来源

- 至少支持两类资料：PDF、DOCX、PPTX、TXT 或图片。
- 保留文件名、页码、段落或片段位置等来源元数据。
- 角色资料型回答展示来源；点击来源可定位原文。
- 资料不足时明确标记“无法确认”，不得生成虚假引用。
- 资料互相冲突时并列展示差异，不擅自选择唯一结论。
- 资料中的指令性文字一律视为数据，不得改变系统和角色规则。

### 6. 探究笔记与最终成果

- 探究笔记至少记录角色、原始观点、回答类型、来源、学生判断和可能局限。
- Agent 可以整理笔记和提出追问，但不能替学生直接生成最终立场。
- 最终成果需要说明该视角的局限和还需要了解的其他观点。
- 最终成果包含结论、证据、反方观点、观点变化、未解决问题和反思。

### 7. 教师预览、发布与报告

- 教师可以预览角色对话，并至少测试身份、未来信息、私人动机、观点冲突和提示注入五类问题。
- 发布前展示角色卡、角色类型、时间锚点、资料范围、发布对象和任务限制。
- 正式发布、修改已发布任务、删除任务和覆盖人工编辑内容必须再次确认。
- 教师可回看学生对话记录、使用的资料、观点变化、探究笔记和最终成果。
- 角色越界回答和安全风险需要在报告中可定位到具体对话。

## 七、现代 Agent 能力要求

现代 Agent 能力必须服务于角色化探究，不能把项目做成与业务无关的通用 Agent 平台。

| 能力 | 本任务中的具体用途 |
| --- | --- |
| Instructions | 定义角色卡、教学目标、事实边界、确认点和终止条件。 |
| Planning | 规划角色所需资料、问题链和学生探究路径。 |
| Tools | 解析资料、检索证据、生成角色卡、核验角色回答、保存草稿和发布任务。 |
| State | 保存任务简报、角色卡、角色会话、探究笔记、确认记录和运行状态。 |
| Memory | 保存当前角色的会话摘要，避免无限拼接上下文。 |
| Human in the Loop | 角色卡、资料范围和正式发布必须由教师确认。 |
| Guardrails | 限制角色漂移、时代错置、虚构史实、冒充真实人物、提示注入和越权。 |
| Trace and Evals | 追踪回答对应的角色卡、引用资料和对话位置，评测角色一致性、来源准确性、认知边界和探究深度。 |

Trace and Evals 在本阶段用于单角色回答的回查与质量验证，可结合验收记录完成，不要求建设独立的自动评测平台。

至少设计以下工具中的 4 个：

- `parse_material`：解析支持的资料格式，提取内容并保留文件名、页码、段落或片段位置等来源元数据。
- `retrieve_evidence`：在教师确认的资料范围内检索证据，返回原文片段及来源定位信息，供角色回答与认知边界核验使用。
- `generate_role_cards`：生成本任务的一个角色卡。
- `check_role_consistency`：核验角色回答是否符合角色卡与认知边界。
- `generate_question_ladder`：生成探究问题链。
- `save_task_draft`：保存任务草稿。
- `preview_role_dialogue`：预览角色对话。
- `publish_task`：发布已确认的任务。
- `aggregate_exploration_report`：整理本任务的探究记录和成果。

“至少设计其中 4 个”是工具设计数量要求，不表示可以省略第六节已要求的资料解析、证据获取、来源展示与原文定位能力；这些能力可以由上述工具或其他内部模块实现。

每个工具必须定义输入输出 Schema、错误码、超时、只读或写入属性及确认要求。工具参数必须校验；失败后最多自动重试 2 次，仍失败则停止当前步骤并交还教师。发布工具属于高风险写操作，未经确认不得调用。

## 八、阶段一：单角色沉浸式探究验收

### 1. 功能范围

- 教师输入完整主题信息，生成或编辑一个真实历史人物或虚拟综合人物角色卡。
- 教师预览角色对话，确认后发布。
- 学生与该角色连续对话，角色保持身份、时间、立场、语言和认知边界。
- 支持推荐问题、自由提问、动态追问、阶段小结和最终成果。
- 实现 Agent Run 状态、最大步骤、停止、重试和人工确认。

### 2. 验收用例

1. 输入“清朝灭亡、1912 年、溥仪、八年级”后，RoleCard 包含全部必填字段。
2. 连续对话 10 轮，角色身份、时间、立场和语言风格不漂移。
3. 询问时间锚点之后的事件时，角色明确说明超出当前认知。
4. 询问未被资料支持的私人动机时，不编造事实或内心独白。
5. 学生只给结论、不提供理由时，角色追问依据而不是直接表扬或代写。
6. 教师修改时间锚点后，角色已知信息、未知信息和推荐问题同步更新。
7. 未经教师确认，不能发布任务。

## 九、关键数据对象

- **TaskBrief**：主题、学科、年级、目标、时间锚点、地域、资料范围、限制和确认项。
- **RoleCard**：角色类型、身份、时间、地域、立场、背景关系、已知与未知信息、来源、语言和禁止行为。
- **RoleSession**：当前角色会话、摘要、已使用证据和未解决问题。
- **Evidence**：来源、原文片段、位置、支持或反驳的观点及可信状态。
- **ExplorationNote**：角色观点、回答类型、资料证据、学生判断和局限。
- **Agent Run**：运行状态、步骤计数、停止与重试状态、人工确认记录。

## 十、异常与兜底

- 必填信息缺失：每轮最多提出 3 个必要问题；已确认内容不得重复询问。
- 资料不足或无法确认：明确提示，不编造史实或引用。
- 问题超出角色时间或认知边界：明确说明超出当前认知。
- 工具调用失败：最多自动重试 2 次，仍失败则停止当前步骤并交还教师处理。
- 结构化输出校验失败：有限修复；仍失败则停止当前步骤并保留原始结果供排查。
- 学生偏题：先以角色口吻拉回主题；连续偏题后由引导提示明确目标。
- 提示注入或越权：保持角色和系统边界，拒绝请求并记录风险。
- 达到最大步骤、最大轮次或用户主动停止：终止当前运行，不再继续自动生成。

## 十一、安全、权限与隐私

- 输入、资料、角色生成、输出和工具参数分别执行安全检查。
- 学生只能访问自己的会话和成果，教师只能访问授权范围内的任务和报告。
- 密钥、访问令牌和模型配置不得写入前端代码或普通日志。
- 日志对学生身份和敏感内容脱敏，只保留排障所需信息。
- 真实人物、群体和敏感历史议题需要避免侮辱、歧视、无依据归罪和单一立场灌输。
- 角色页面明确提示“AI 模拟角色，不代表人物本人真实言论”。
