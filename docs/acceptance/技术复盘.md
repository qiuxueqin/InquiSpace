# 阶段一 P6 技术复盘

## 1. 交付结论

P0～P5 已形成教师创建与确认发布、资料解析与来源定位、固定单角色对话、停止/重试、自动学习报告及教师图文回看的业务闭环。P6 不增加新业务表或公共 API，而是把阶段一完成定义转化为可复跑证据：三个固定主题、每主题 10 轮真实模型脚本、七维人工评分、故障/权限回归、演示脚本和本复盘。

真实模型质量不是单元测试可证明的确定性属性。运行器将“结构与来源约束通过”和“人工语义验收通过”分开：程序负责 Schema、证据 ID 范围、模型/Prompt 版本和错误终态；教师或评审负责身份/语言是否漂移、来源是否真正支持、边界表达是否充分以及追问是否具有探究深度。只有二者都通过，才能声明三主题验收完成。

## 2. 设计取舍

### 单角色 + 显式工作流

首版没有引入通用 Agent 框架、向量数据库或外部队列。角色生成、预检、对话核验和报告整理均由显式 Python 工作流与状态表约束，便于把每个状态、确认、重试和终态对应到验收要求。代价是单进程容量协调和后台恢复能力有限，不适合未经压测的整班并发或多实例部署。

### 可定位证据优先于“模型知道”

事实块必须引用本轮候选 Evidence，引用位置由数据库派生，不接受模型生成文件路径。无支持时输出 unknown，而不是使用模型记忆伪造出处。BM25 对受控小规模中文材料足够简单、可回查，但会漏掉同义表达和冲突片段；P6 三主题必须人工检查召回与原文支持，结果决定是否需要扩展查询或改进检索，不预先升级基础设施。

### 分段核验后展示

回答先生成完整 JSONL 行，再逐块执行结构、引用范围和模型语义核验，合格块才落库并通过 SSE 展示。这样牺牲首段延迟，换取“不让未核验事实先显示”。同一模型进行生成与核验仍可能重复偏差，因此 P6 保留人工评分，不能把自动核验当作最终真相。

### 自动报告不代写

学习报告固定输入快照，只引用学生原话和已终结回答；程序计算次数，模型不填写统计。没有表达的结论进入 missingAspects，不从角色回答补成学生观点。更正追加而不覆盖原话或旧报告，保留可审计历史。

### P6 验收工具隔离业务数据

P6 运行器使用正式 DeepSeek 适配器和当前对话协议，但读取独立 JSON 案例并写脱敏记录，不写业务数据库、不创建正式任务或学生记录。这样能重复比较模型版本而不污染课堂数据；代价是它不能代替一次真实浏览器纵向演示，因此另有 5～10 分钟录制脚本。

## 3. 典型失败模式与当前防线

| 失败模式 | 影响 | 当前防线 | P6 复核点 |
| --- | --- | --- | --- |
| 连续对话后身份、年份或虚拟标识漂移 | 角色可信度失效 | 固定 RoleSession 快照、最近消息/摘要、逐块角色核验 | 三主题各 10 轮人工检查身份、时间、地域、立场和语言 |
| 使用时间锚点之后的信息 | 后见知识冒充当时认知 | known/unknown 范围、future_information 预检、回答核验 | 每主题固定未来事件问题，检查语义而非关键词 |
| 编造私人动机或亲历 | 将推测包装成史实 | 角色禁止行为、无依据 unknown、回答核验 | 固定“秘密/内心”问题及无依据亲历问题 |
| 引用存在但不支持回答 | 形式上有来源、实质错误 | 候选范围、Citation 派生、语义核验 | 人工逐条打开夹具原文核对支持关系 |
| 冲突材料被静默删去一方 | 单一立场灌输 | disputed 标记、Prompt 要求并列、核验记录 | 三主题固定冲突问题，检查观点与局限是否并列 |
| 资料内提示注入改变角色 | 数据越权为指令 | 资料按数据注入，无工具权限；Prompt 注入预检 | 工业革命夹具含显式恶意指令并固定提问 |
| 学生只给结论时被直接表扬或代写 | 探究退化为答案生成 | FollowUpOutput、禁止代写、报告只归纳原话 | 固定 conclusion-only/reflection 两轮 |
| 模型超时、限流、截断或坏 JSON | 卡住运行或损坏状态 | 稳定错误码、有限重试、步骤/时限、终态不可逆 | HTTP 故障矩阵、截断流、连接失败和容量释放测试 |
| 停止后仍写入新块 | 用户控制失效 | cancelRequestedAt 持久化、写块前重查、终态竞争 | 停止/partial/重试回归与演示 |
| 跨学生读取会话、Run、文件或报告 | 隐私泄漏 | Cookie 身份、对象授权、不可见统一 404、SSE 心跳重查 | 双学生交叉访问矩阵与撤权测试 |
| 旧报告覆盖新学习快照 | 报告与当前过程不一致 | learningRevision/inputHash、不可变 ready、旧请求 superseded | 报告并发、重试和 aggregateToken 测试 |

## 4. 故障注入结果解释

自动化故障注入只证明已覆盖的状态与错误映射符合契约，不证明外部供应商永不出现新错误。当前覆盖供应商鉴权/配置错误、限流、服务端错误、网络连接、超时、结构错误、流截断，以及进程中断、解析失败、容量耗尽、revision 竞争、确认过期、取消与报告恢复。

记录只保存稳定错误码和最小排障摘要，不保存 API 密钥、完整提示或供应商可能回显的敏感正文。生产排障仍需受控日志与留存政策；普通师生页面不展示原始 RunStep、Prompt 或模型响应。

## 5. 未解决边界

- 真实模型输出具有概率性。模型名相同也可能随供应商服务更新而变化；每次正式验收都要记录日期、模型、effort、Prompt 版本和案例哈希。
- 单进程 FastAPI BackgroundTasks + SQLite/WAL 能满足阶段一小规模验收，但没有跨进程抢占、分布式锁或外部队列。多 worker 会破坏当前容量与取消假设。
- 资料只支持带文本层 PDF 与 UTF-8 TXT；扫描 PDF 需要 OCR，DOCX/PPTX/图片不在首版范围。
- BM25 可能漏召回中文同义表达；三主题材料较小，不能外推到大规模语料库。
- 停止可阻止后续应用落库，但无法保证撤回供应商已经接收的计算。
- 自动核验与学习报告不替代教师审核，不应被解释为评分学生能力或判断心理状态。
- 当前未给出生产并发、延迟、成本、备份 RPO/RTO 或可用性承诺；这些需要真实环境压测和恢复演练。

## 6. 后续改进优先级

1. 在有密钥的受控环境完整跑三主题并进行双人复核；对任何阻断失败修订 Prompt/规则后完整复跑，不只重跑失败轮。
2. 使用获准的真实 PDF/TXT 教材替换验收夹具，保留授权与版本哈希；扩充中文同义问法和冲突材料召回集。
3. 在浏览器环境补关键 Playwright 闭环与视觉回归，覆盖 PDF.js/TXT 定位、停止/重连、报告图表和导出。
4. 上线评估前完成 HTTPS、Secure Cookie、备份/恢复演练、日志脱敏审查、密钥轮换和实际课堂并发压测。
5. 只有在多实例或长任务需求明确后，再评估 PostgreSQL、对象存储和外部队列；不要为阶段一验收提前引入复杂基础设施。

## 7. 完成判定

P6 工程交付完成需同时具备：案例包校验通过、全量自动化检查通过、真实模型三主题运行记录、人工七维评分全部通过、5～10 分钟视频完成并登记，以及遗留边界明确。若缺少模型凭据或浏览器录制条件，可以完成工具和离线回归，但必须把真实模型与视频标为待执行，不能写成已通过。
